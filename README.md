# CS 250 Reflection

## How do I interpret user needs and implement them into a program? How does creating user stories help with this?

I interpret user needs by first identifying what the user is trying to accomplish, then breaking that need into specific functionality that can be developed and tested. 
User stories help by keeping the focus on the user instead of only on the technical solution. In the SNHU Travel project, user stories helped turn general requests into features such as destination recommendations, price limits, and 
ranked results. Acceptance criteria then made those needs more specific and gave the team a way to determine whether the feature was completed successfully.

## How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?

I approach development by first understanding the problem, requirements, and expected outcome before writing code. I then prefer to build in smaller pieces, test as I go, 
and adjust when new information becomes available. From this course, I would like to continue using practices such as user stories, backlog prioritization, frequent testing, short development increments, and regular communication. 
The SNHU Travel project showed me that requirements can change during development, and Agile provides a way to adapt without throwing away work that is still useful.

## What does it mean to be a good team member in software development?

Being a good team member means communicating clearly, being dependable, asking questions when requirements are unclear, and helping the team work toward the same goal. 
It also means being open to feedback and willing to adjust when priorities change. Different roles on a Scrum Team have different responsibilities, but the project works best when the Product Owner, Scrum Master, Developers, and 
testers share information instead of working in isolation.
